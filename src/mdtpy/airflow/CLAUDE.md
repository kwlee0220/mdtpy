# CLAUDE.md — mdtpy/airflow

This file provides guidance to Claude Code (claude.ai/code) when working with the `mdtpy.airflow` subpackage.

For repository-wide conventions and the broader architecture, see `../../../CLAUDE.md`. Operator-level usage (signatures, output-semantics comparison, examples) is in `operator/README.md`; package-level usage (`DagContext`, `DagTaskArgument`, quick start) is in `README.md` next to this file; `doc/programming_guide.md` §8 has a short tutorial. Keep all three in step when the public API changes.

## What this package is

`mdtpy.airflow` is an **optional** subpackage that wraps MDT operations as Airflow task bodies. It is **not** auto-imported by `mdtpy/__init__.py`, so the core library does not depend on Airflow. Its main consumer is the DAG files generated by `mdt-workflow` (see "Public names are a contract" below).

Four modules (`operator/` is a package) / three layered abstractions:

1. **`DagContext`** (`dag_context.py`) — runtime adapter.
   - `LocalDagContext(task_id, mdt_inst_url)` keeps task outputs in a class-level dict for in-process testing, takes `mdt_inst_url` as a **required** argument, connects in `__init__`, and never imports Airflow.
   - `AirflowDagContext(mdt_manager_url=None)` imports `airflow.sdk.Variable` **inside `__init__`** (so constructing one requires Airflow), falls back to the `mdt_manager_url` Variable when no URL is given, and calls `connect()` in `__init__` too; the `mdt_manager` property just returns that manager. `connect()` only builds a client object around the URL (no server round-trip), and operators build this context inside `run()` when none is passed, so construction happens at task-run time anyway. Making it lazy would only pay off if `Variable.get` were deferred as well (for contexts built at DAG-parse time), which no caller does today. `task_id` comes from `get_current_context()['ti']`. Task outputs go through XCom (`'task_output'` key) in the `@type`/`value` polymorphic JSON form via the module-level helpers `_to_task_output_json_node` (push) / `_parse_task_output_json_node` (pull), because XCom only accepts JSON-serializable values.
2. **`DagTaskArgument`** (`dag_task_argument.py`) — describes how to obtain an input value at task runtime; `get(context) -> ArgumentValue` (= `ElementValue | ElementReference | basyx model.SubmodelElement`). Factory helpers:
   - `task_output(task_id, argument)` → `TaskOutputArgument`: `context.get_task_output(...)` → `ElementValue`.
   - `reference(ref_string)` → `ElementReferenceArgument`: resolves the ref, then returns the **`SubmodelElement` itself** for `timeseries:` refs (`ref.read()`), the **`ElementReference` itself** when the value is a `FileValue` (so File inputs can be passed by reference), and the read **value** otherwise.
   - `literal(value)` → `LiteralArgument`: keeps an `ElementValue` as-is, otherwise wraps it with `mdt_value()`, which only accepts scalars (str/bool/int/float/timedelta) — anything else raises `ValueError` at construction. DAGs generated by `mdt-workflow` pass `literal(mdtpy.value.parse_json_node({...}))`, so typed and structured literals (collection, list, File, Range, DateTime, Long, ...) survive.
   - `sink(ref_string)` → just `mdtpy.reference(ref_string)`: an `ElementReference` **write target** for `outputs`, not a `DagTaskArgument`.
3. **`Operator`** (`operator/` package) — task body; `run(context=None)` (defaults to `AirflowDagContext()`). The `Operator` ABC plus the type aliases (`DagTaskInputArgument = DagTaskArgument`, `DagTaskOutputArgument = ElementReferenceArgument`) live in `operator/operator.py`. Each concrete operator is in its own module and re-exported from `operator/__init__.py`, so `from mdtpy.airflow.operator import ...` and `from mdtpy.airflow import ...` both work.

| Operator | Module | Constructor | Task outputs passed downstream |
|---|---|---|---|
| `SetElementOperator` | `set_element.py` | `(inputs, outputs={})` — `inputs['source']` required; `outputs`, if given, must contain `'target'` (both `ValueError` at construction) | always `{'target': value}` |
| `OperationSubmodelOperator` | `operation_submodel.py` | `(instance, submodel, *, inputs, outputs={})` | everything `invoke()` returns |
| `AASOperationOperator` | `aas_operation.py` | `(instance, submodel, path, *, inputs, outputs={})` — `path` is the Operation idShort path | everything returned |
| `RestfulAsyncRpcOperator` | `restful_async_rpc.py` | `(base_url, op_endpoint, *, inputs, outputs={})` | everything returned (non-`ElementValue` wrapped with `mdt_value()`) |
| `RestfulRpcOperator` | `restful_rpc.py` | `(op_url, *, timeout=None, inputs, outputs={})` | **declared only**; a declared output that is not returned → `KeyError`; `None` target = pass downstream without recording |
| `PythonScriptOperator` | `python_script.py` | `(script, *, inputs, outputs={})` | **everything the script put in its `outputs` dict**; the `outputs` argument only says what to record where (a target the script did not fill is skipped; a `None` target is accepted but has no effect) |

Operator-specific arguments are passed **directly** as constructor arguments (not via a dict); `inputs`/`outputs` are always keyword dicts.

`types.py` holds `ArgumentValue = ElementValue | ElementReference | model.SubmodelElement` and `TaskOutput = ElementValue`.

The `__init__.py` re-exports the modules via `from .X import *`. Callers do `from mdtpy.airflow import LocalDagContext, OperationSubmodelOperator, reference, task_output, sink, ...`.

**Adding a new operator** spans three repos (this package, `mdt-client` task types, `mdt-workflow` DAG generator) and has a required deploy order. Follow `~/development/mdt/mdt-workflow/docs/adding-operator.md` (Korean) step by step.

## Architecture quirks worth knowing

- **Public names are a contract with generated DAGs.** The `mdt-workflow` template (`airflow_dag.peb`) emits `import mdtpy`, `from mdtpy.airflow.operator import (AASOperationOperator, RestfulAsyncRpcOperator, SetElementOperator, OperationSubmodelOperator, RestfulRpcOperator, PythonScriptOperator)`, the helpers `mdtpy.airflow.reference/literal/task_output/sink(...)`, `mdtpy.value.parse_json_node(...)`, and operator constructor keyword names (`instance`, `submodel`, `path`, `base_url`, `op_endpoint`, `op_url`, `timeout`, `script`, `inputs`, `outputs`). Renaming any of these breaks DAG files that are already generated and deployed — change them together with `mdt-workflow`.
- **Deferred Airflow imports.** `airflow.sdk` is imported only inside `AirflowDagContext` methods (`__init__`, `task_instance`). Don't hoist the imports to module top — that would force every `mdtpy.airflow` consumer to have Airflow installed.
- **Two different `reference()` functions.** The airflow `reference(ref_string)` builds an **input spec** (`ElementReferenceArgument`). A **write target** — `SetElementOperator`'s `outputs['target']` and the values of every other operator's `outputs` — must be an actual `ElementReference`: build it with airflow `sink()` (equivalently `mdtpy.reference(...)`), not the airflow `reference()`.
- **Output handling is not uniform across operators.** `RestfulRpcOperator`, `PythonScriptOperator` and `RestfulAsyncRpcOperator` convert **all** outputs to `ElementValue` first (declared outputs for `RestfulRpc`, every script output for `PythonScript`, every result for `RestfulAsyncRpc`), then write the targets, then pass the same converted dict to `set_task_outputs` (no partial writes on a conversion failure). `AASOperationOperator` writes each returned value as it goes; `OperationSubmodelOperator` merges `{**in_args, **outputs}` into `invoke()`, and `OperationSubmodelService.invoke` writes each result to the `ElementReference` passed for that id. New operators should follow the convert-first pattern.
- **`PythonScriptOperator` runs `exec(script, namespace)` with one dict as globals and locals** (`{'inputs': resolved inputs, 'outputs': {}}`), so top-level names and imports are visible inside functions/lambdas/generators. The script produces outputs by **filling the `outputs` dict** (`outputs['name'] = value`); every entry becomes a task output (so every entry must be convertible by `to_element_value()` — scalars via `mdt_value()`, `dict` → `ElementCollectionValue`, `list`/`tuple` → `ElementListValue`, recursively), and assigning a same-named variable does nothing. Only this operator converts containers: `RestfulRpcOperator`/`RestfulAsyncRpcOperator` still use scalar-only `mdt_value()`, because their results are remote JSON where a `dict` may already be a typed `{"@type": ...}` ElementValue node — blindly turning it into a collection would misread it. This pass-everything contract is deliberate: the operator is meant for small glue logic between two tasks, so its outputs normally need no declaration. The script is trusted DAG-author code — never assemble it from external input.
- **`RestfulRpcOperator` encodes inputs itself** with `encode_argument_to_json_node`, because the synchronous `RESTfulRpcClient` needs JSON-ready values (the async client used by `RestfulAsyncRpcOperator` encodes internally).
- **`SetElementOperator` validates at construction** (`ValueError("Input argument 'source' is required")`, and `outputs` without `'target'` is rejected). It stores the value under the `'target'` key in task output — downstream tasks reference it with `task_output(task_id, 'target')`.
- **`LocalDagContext.__TASK_OUTPUT` is a class variable**, so output state leaks across instances within the same process. Tests that exercise more than one DAG should reset it explicitly.
- **`DagContext` is fully abstract — six members**: `task_id`, `mdt_manager`, `get_submodel`, `resolve_reference`, `get_task_output`, `set_task_outputs`. `mdt_manager` is a `@property @abstractmethod`, so a subclass must override it **at class level** (an instance attribute set in `__init__` does NOT satisfy it — that mistake makes the class un-instantiable).
- **`resolve_reference` asymmetry is intentional.** `LocalDagContext` wraps the string lazily via `mdtpy.ref.reference()` (no HTTP at resolve time); `AirflowDagContext` uses `MDTInstanceManager.resolve_reference()`, which queries the manager for the `service_url` eagerly.
- **`TaskOutput` is `ElementValue`.** Both contexts' `set_task_outputs` reject a non-`ElementValue` value with `TypeError` via the shared `_check_task_output` helper (Airflow through `_to_task_output_json_node`, Local directly), so the contract is enforced uniformly.
- **Missing task-output lookups raise `KeyError`** with a message naming the task/argument (both contexts) — not `assert`, so behavior survives `python -O`.
- **`AirflowDagContext.__repr__` is side-effect-free** (only shows `mdt_manager_url`). Don't add `get_current_context()`/XCom calls back into it — it must be safe outside a running task (DAG parsing, debuggers).

## File-input handling

The value-vs-reference decision lives in `ElementReferenceArgument.get()`: it reads the referenced value and returns it, **except** when the value is a `FileValue` — then it returns the `ElementReference` itself (and for `timeseries:` refs it returns the `SubmodelElement`). So `OperationSubmodelOperator` (which passes each `arg.get(context)` straight into `invoke()`) hands File inputs to the operation by reference and everything else by value. `SetElementOperator` always wants a value, so it wraps the result in `_to_element_value` (which re-reads a File reference into its `FileValue`). A File `source` in `SetElementOperator` is therefore read twice (once in `get()` to detect the File, once in `_to_element_value`); an uncommon path, but not free.

## Known issues

- **`mdtpy.airflow.operator` as an attribute is the `operator.py` module, not the package.** `operator/__init__.py` has no `__all__`, so `from .operator import *` in `mdtpy/airflow/__init__.py` also copies the package's submodule attributes — including `operator` (= `operator/operator.py`), which overwrites the `mdtpy.airflow.operator` attribute (`set_element`, `restful_async_rpc`, ... leak into `mdtpy.airflow` too). `from mdtpy.airflow.operator import X` still works (it goes through `sys.modules`; generated DAGs use this form), but attribute access, `import mdtpy.airflow.operator as op`, and string targets like `patch("mdtpy.airflow.operator.restful_async_rpc.RESTfulAsyncRpcClient")` resolve to the wrong module. In tests, import the submodule (`from mdtpy.airflow.operator import restful_async_rpc`) and use `patch.object`.
- **`RestfulRpcOperator` pass-only outputs are not reachable from generated DAGs.** The `mdt-workflow` workflow model cannot express a `None` output target (output arguments must be references), so they work only in hand-written DAGs. `PythonScriptOperator` (task type `mdt.task.PythonScriptTask`, script in the `script` option) does not need them — it passes every script output.

## Testing

Unit tests live in `tests/test_airflow.py` (run with `make test`; no Airflow install needed). Patterns used there, for extending coverage:

- `LocalDagContext` is created with `mdtpy.airflow.dag_context.connect` patched (no real HTTP) — the `local_ctx` fixture.
- An autouse fixture resets `LocalDagContext._LocalDagContext__TASK_OUTPUT` around each test.
- `AirflowDagContext` is built via `object.__new__` (bypassing the `airflow.sdk` import in `__init__`) and its `task_instance` property is patched with a mock TaskInstance whose `xcom_push`/`xcom_pull` round-trip through `json.dumps`/`json.loads` to reproduce XCom's JSON-serializability constraint. The name-mangled private URL attribute is `ctx._AirflowDagContext__mdt_manager_url`. To exercise the real `__init__` (Variable lookup + `connect()`), inject a fake `airflow.sdk` with `patch.dict(sys.modules, {...})` and patch `mdtpy.airflow.dag_context.connect` (see `_fake_airflow_sdk`).
- Operator tests mostly pass a `MagicMock` context and assert `context.set_task_outputs.assert_called_once_with({...})`; this is safe because `PropertyValue.__eq__` compares types (a raw `42` never equals `mdt_value(42)`). Use `local_ctx` when the test must go through the real `_check_task_output` (e.g. raw-value outputs).
